Ensemble

Multi-chat orchestration for Claude Code. One Maestro conducts many Agents — building, testing, and shipping real software autonomously while you’re at work, asleep, or out with your phone.

# Install (one-time)
/plugin marketplace add KiwiMaddog2020/claude-ensemble
/plugin install ensemble@claude-ensemble

# Boot the Maestro in any new chat
/ensemble:maestro

# Onboard an Agent for a specific repo (from inside that repo)
/ensemble:agent-onboard

What this solves

Running many Claude Code chats at once feels powerful — until two of them spin a VM on the same machine, or both rewrite state.json, or you forget which one you told to ship. Ensemble gives every chat a role, every action a lock, and you a single kill-switch.

The cast

  • Maestro — one chat, one baton. Coordinates, ranks top recs across projects, owns orchestrator:* scheduled tasks. Never holds the autopilot lock.
  • Agents — the other chats. Each one is scoped to a single project (repo), reads a per-project charter, reports status in a rapid-fire format, and acquires the autopilot mutex before any work.

What’s in v2.0

The v2.0 contract sweep (2026-04-26) added eight operating directives + a three-layer mutex + Tier 1 hardening:

Three-layer autopilot mutex

Layer What it prevents Configurable?
Workshop lock (kernel-enforced via PreToolUse hook) Two chats grabbing computer/browser simultaneously No, always on
Per-project spawn lock (atomic mkdir per slug) Same-repo dual-fire (file stomps) No, always on
Resource floor (RAM/CPU pre-check) Spawning under critical system pressure Yes, opt-in default OFF

Plus a user-controlled cap: max_concurrent_autopilots (default 2; adjustable via verbal set max autopilots to N or PWA dashboard). Cap-hit = queue with 5-min timeout.

Six-state project lifecycle

BUILDING → LAUNCH PREP → WARMER ⇄ R&D ⇄ UPDATES → HIBERNATING
pre-launch  pre-launch    live triangle (bidirectional)   archive

Every project’s chats/<slug>.json carries a state field. Auto-transitions at G1/G7/G8. Manual override via verbal set <slug> to <state> or PWA dashboard pill. Live triangle (Warmer/R&D/Updates) is bidirectional.

Operating directives

Directive What
Smart handoff Self-monitor context: 80% warn, 90% auto-stage, 95% hard-stop. Each chat dies cleanly with paste-ready resume prompt.
Turbo mode Liberal turbo signal → AFK batch coding mode. All approvals up-front, then run autonomously until completion. Safety gates still fire.
Outside-the-box thinking Priority 1 operating posture. Build fancy debug/calibration tools when warranted. Canonical: isolate each CSS effect on its own row to spot a glitch.
Feedback pipeline Sunday 6am aggregator pulls from each live project’s channel (GitHub Issues / Formspree / email / Discord), compiles per-project briefings. Strict plan-then-approve gate for live products.
Rapid-fire toggle state.json.rapid_fire_enabled, default true. ON = AskUserQuestion at decisions. Every call reserves slot 4 for “Disable Rapid Fire Mode” — one-click escape hatch.
Lint discipline .editorconfig + markdownlint + yamllint + ruff + prettier configs at repo root. CI gates lint on every PR. Surgical edits never introduce new lint failures.
Active/inactive control Per-chat active flag — set <slug> active/inactive in any chat. Inactive chats skipped by routines but state preserved.
Flow continuity Never offer “pause” / “stop” / “sleep on it” — user dictates when work ceases.

Tier 1 hardening (2026-04-26)

Protection Purpose
caffeinate -i wrap Mac can’t idle-sleep mid-autopilot, suspending the subprocess. Honored via caffeinate_during_autopilot (default true).
Battery awareness Optional require_ac_power flag refuses fires on battery. Default off (opt-in).
Disk pre-flight min_free_disk_gb threshold (default 5). Refuses fires under threshold.
Log rotation Sunday 5am scheduled task. 30/60/90-day retention per directory. Stops runs/ from growing unbounded.

Menu bar indicator (SwiftBar)

A 30-line shell script that drops into SwiftBar and shows ☕ + active autopilot count in the Mac menu bar. Click → project list with start times, queued autopilots, Stop All button, dashboard link. One-shot installer at plugins/ensemble/integrations/swiftbar/setup.sh.

Safety by design (foundations, unchanged from v1)

  • Atomic autopilot lock — POSIX mkdir, one winner, no races. Filesystem-enforced.
  • Hooks, not vibes — PreToolUse hook hard-blocks VM tools when state disagrees. Fires before permission-mode checks, so it blocks even under --dangerously-skip-permissions.
  • Distributed kill-switch — say ***ORCHESTRATOR OFF*** verbatim in any chat. Six-phase cascade releases the lock, pauses automations, flips the system to direct mode. Any chat can execute; protocol handles races.
  • Fail closed — if shared state.json goes missing, every VM tool is blocked.

Slash commands this plugin provides

Command What it does
/ensemble:maestro Boot the current chat as the Maestro. Reads its identity contract, scans status files, surfaces the cross-project top rec.
/ensemble:agent-onboard Onboard the current chat as an Agent scoped to cwd. Runs discovery + adaptive interview + writes charter + status file.
/ensemble:autopilot N Fire an N-minute autopilot session on the current project (wraps spawn lock + caffeinate).
/active <slug> Set a project active in routine rotations.
/inactive <slug> Set a project inactive (state preserved).
/projects Roster of all chats with state, active flag, autopilot eligibility.

Hooks this plugin registers

Auto-registered by the plugin runtime; no ~/.claude/settings.json edits needed.

Event Matcher What it does
PreToolUse mcp__(computer-use\|Claude_Preview\|Claude_in_Chrome)__.* Blocks VM tools when mode≠orchestrated or another Agent holds the workshop lock.
SessionStart startup\|resume\|clear Prints [ORCHESTRATOR] hard-enforcement active (or MISSING) into context.

Optional extensions

After core install, the Maestro can walk you through:

  • Scheduled routines — Morning Briefing, Evening Planning, Overnight Heavy, Workday Pulse, Dashboard Update, Log Rotation. Mode-gated; respect your work hours. Most fire via Mac scheduled-tasks; mobile-triggered via cloud Routines.
  • Mobile dispatch — iOS Shortcuts + Termius/Tailscale to fire autopilot from your phone. One tap to kick off work; one tap to kill everything.
  • PWA dashboard — Live cross-project completion roster with state pills (six colors), tap-to-fire-autopilot, embedded chat. Auto-refreshes 3× daily, installable to phone home screen.
  • SwiftBar menu bar — bash plugins/ensemble/integrations/swiftbar/setup.sh installs SwiftBar + symlinks the plugin + configures everything in one shot.
  • Cross-machine sync — companion repo ensemble-config syncs templates/memory/scripts between Mac (bin-mac/) and Windows (bin-win/). Full PowerShell parity for the three-layer mutex.

Files

Writable user state (${CLAUDE_PLUGIN_DATA}): - state.json — global mode, mutex view, cascade state, concurrency knobs - state.lock.d/ — atomic workshop lock (only exists while held) - state.spawn-lock-<slug>.d/ — per-project spawn locks (only exist while held) - chats/<slug>.json — one per Agent; status + heartbeat + state + top rec - work_hours.json — your schedule gate for routines - briefings/, queue/, pulse/, runs/ — routine outputs - lock_steals.log — audit of stale-lock steals
