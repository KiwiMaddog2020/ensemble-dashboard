Pre-Flip Checklist

**Status:** active · last reviewed 2026-05-03

source: docs/operations/PRE_FLIP_CHECKLIST.md

The go-live runbook. Every step Kevin needs to take before flipping the public switch on ensemble.tld. Cross-references the launch package in docs/launch/.

Last updated 2026-04-29. Owner: Kevin (sole operator). Target T-0: TBD — gated by quality, not date. See GTM_PLAN §2 Wave 4.

How this doc is used

This is a checklist, not a narrative. Walk it top-to-bottom in the listed window. Every box must be ticked before the next window starts. If a box can’t be ticked, the launch slips — that’s the contract.

The cadence: - T-7 days — full launch package frozen. No more code merges except hotfixes. - T-3 days — operational backbone verified end-to-end. - T-1 day — content drafted, reviewed, queued. - T-0 — the launch day itself, scripted hour-by-hour. - T+1 day — first response cycle. - T+7 days — first retro + Product Hunt scheduling.

Rollback procedures are at the bottom. Read them before T-7 so they’re already familiar by the time something breaks.

T-7 days — code freeze

Goal: the bits stop moving so the bits can be tested.

Code & infra

  • [ ] All 6 chunk warp fan-outs merged into main + tests green
  • [ ] Live PWA matches main (latest dashboard-fire ran clean)
  • [ ] Phase 2.4 E2E smoke passing (signup → procedural fill → publish → grid → fly-in)
  • [ ] Color contrast audit run + remediated (WCAG 2.1 AA across every page)
  • [ ] STATE_PATH NameError fix verified (no 500s on /set-config, /save-room, /publish)
  • [ ] iframe sandbox: allow-same-origin confirmed dropped, manual paste-test of malicious HTML
  • [ ] Privacy Policy + ToS reviewed by Canadian privacy counsel (sign-off in writing)
  • [ ] DMCA contact email forwarding works (test send to copyright@ensemble.tld lands in inbox within 60s)
  • [ ] No commented-out code, no debug console.log, no TODO: remove before launch strings remain in shipped files

Content

  • [ ] Manifesto blog post drafted (see launch/MANIFESTO_BLOG_POST.md)
  • [ ] Show HN post drafted (see launch/SHOW_HN_POST.md)
  • [ ] Product Hunt assets prepared (see launch/PRODUCT_HUNT_ASSETS.md)
  • [ ] Email templates ready (see launch/EMAIL_TEMPLATES.md)
  • [ ] Press kit assembled (see launch/PRESS_KIT.md)

Beta seed

  • [ ] Wave 0 dogfooding complete: Kevin’s own Studio used daily for 14+ consecutive days
  • [ ] 25 Wave-2 closed-beta members onboarded with at least one save + one publish each
  • [ ] At least 10 stand-out showcase pages exist (the curation set for Show HN + PH)

T-3 days — operational backbone

Goal: every external dependency tested in anger.

Auth & access

  • [ ] Cloudflare Access deployed + tested with 3 different identity providers (Google, GitHub, Apple)
  • [ ] Magic-link email path verified end-to-end on a fresh inbox
  • [ ] Account deletion path verified end-to-end (data actually gone from R2 + D1)

DNS

  • [ ] DNS records prepared and staged (A, CNAME, MX, TXT for SPF/DKIM/DMARC)
  • [ ] TTL lowered to 300s on the apex record so the swap is reversible inside 5 minutes
  • [ ] dig +short ensemble.tld returns the expected staging IP from a non-Cloudflare resolver

Billing

  • [ ] Stripe products + prices configured: Studio Pro $12/mo + $108/yr ($9/mo equivalent)
  • [ ] Stripe webhook URL registered + smoke-tested with stripe listen --forward-to
  • [ ] One real test charge run with a real card (Kevin’s own), refunded same-day
  • [ ] Pro decorator gate verified on three Pro-only routes (server-side, not just UI hide)

Monitoring

  • [ ] UptimeRobot endpoints configured (every 5 min, 3 regions: US-East, EU-West, AP-Southeast)
  • [ ] Cloudflare Web Analytics deployed + verified data flowing within 1 hour of a test pageview
  • [ ] Sentry DSN configured + smoke error sent + alert rules verified (Kevin gets paged within 60s)
  • [ ] Anthropic spend cap thresholds tuned ($X/day, $Y/month — values locked in safety_constraints.md)
  • [ ] CFWA dashboard bookmarked + checked once

Runbooks

  • [ ] Uptime alert runbook exists and is linked from UptimeRobot (“if site is down, do this”)
  • [ ] Cloudflare Access lockout runbook exists (“if I lock myself out, do this”)
  • [ ] Anthropic spend cap-exceeded runbook exists (“if the cap fires, do this”)

T-1 day — content frozen

Goal: every word that will be published in the next 48 hours has been read by Kevin twice.

Drafts

  • [ ] Show HN post drafted + reviewed (NOT submitted yet)
  • [ ] Show HN founder’s first comment drafted (the elaboration on the most-likely top question)
  • [ ] Product Hunt listing prepared (NOT scheduled yet — PH launches T+7, see Wave 4)
  • [ ] Manifesto blog post drafted, reviewed, scheduled to publish at T-0 10:00
  • [ ] Twitter / X thread drafted (8 tweets, see launch/TWITTER_BLUESKY_THREAD.md)
  • [ ] Bluesky thread drafted (3 posts, slower vibe)
  • [ ] Wave-2 closed-beta invitation email drafted (launch/EMAIL_TEMPLATES.md)
  • [ ] Wave-1 stealth waitlist activation email drafted

Lists

  • [ ] Wave 1 waitlist exported to a CSV (200 names, hand-written notes per person)
  • [ ] First batch of invitations queued (the 25 Wave-2 people from MANIFESTO §6)
  • [ ] Personal DM list ready (~10 highest-leverage announcements: Hacker News-active friends, Bluesky-active makers)

Assets

  • [ ] Hero GIF rendered + compressed (≤2MB, 1280×800)
  • [ ] 3 gallery PNGs rendered (1280×800 each)
  • [ ] Demo video (30s MP4, 1080p, no audio narration — pure-mechanics)
  • [ ] OG image baseline tested across Twitter / Bluesky / iMessage / Slack (no broken thumbnails)

Final review

  • [ ] Read launch/MANIFESTO_BLOG_POST.md once aloud — voice should sound like Kevin, not like marketing
  • [ ] Read launch/SHOW_HN_POST.md — does it pass the HN sniff test? (no buzzwords, no superlatives, no claims that aren’t demonstrably true)

T-0 — launch day, scripted hour-by-hour

All times in Kevin’s local timezone (America/Toronto). Adjust if travelling.

06:00 — DNS swap

  1. Confirm UptimeRobot is green for the staging endpoint.
  2. Update apex A record to point at the production Cloudflare zone.
  3. Wait 90s; dig +short ensemble.tld @1.1.1.1 should return the new IP.
  4. Hit https://ensemble.tld from a fresh browser session — does the homepage render?
  5. Tick: DNS done.

06:30 — Auth verification

  1. Sign up with a real but disposable email (e.g., kevin+launch-test@…).
  2. Verify magic-link delivery + sign-in.
  3. Verify Cloudflare Access challenge for /admin (still locked to Kevin).
  4. Tick: Auth done.

07:00 — End-to-end smoke

Walk the canonical happy path with a stopwatch: 1. Sign up with a fresh handle. 2. Procedural fill seeds the canvas. 3. Publish the canvas. 4. Confirm it appears in /index.html showcase grid. 5. Click-to-fly-in: visitor lands inside the Studio. 6. From inside the Studio, click an interactive sprite (vinyl, arcade cabinet, book) — interaction fires. 7. Total wall-clock: target ≤ 2 minutes. 8. Tick: smoke green.

08:00 — Wave-2 closed-beta invitations

  1. Send the 25 personal invitations from the email templates doc.
  2. Each invitation includes their reserved handle + a one-line “I made this with you in mind because of [specific work].”
  3. Don’t bcc — every email is one-to-one.
  4. Tick: invitations sent.

09:00 — Show HN submission

  1. Read launch/SHOW_HN_POST.md one final time.
  2. Submit at https://news.ycombinator.com/submit (NOT scheduled — submitted directly).
  3. Within 5 minutes of submission, post the founder’s first comment (HN convention).
  4. Pin the HN link in the personal Twitter/Bluesky bio.
  5. Tick: HN live.

09:30 — Schedule Product Hunt

  1. Create the PH draft from launch/PRODUCT_HUNT_ASSETS.md.
  2. Schedule for the following Tuesday at 12:01 AM PT (T+7 — see GTM_PLAN.md Wave 4 timing).
  3. Don’t launch PH same-day as Show HN — let HN organic settle first.
  4. Tick: PH scheduled.

10:00 — Manifesto blog post publishes

  1. Auto-scheduled the night before; verify it went live at the top of the hour.
  2. Cross-link from the homepage hero CTA: “Read the launch story →”.
  3. Tick: blog live.

10:30 — Twitter / Bluesky thread

  1. Post the 8-tweet thread on Twitter / X.
  2. Post the 3-post thread on Bluesky.
  3. Don’t @-tag press; let the work speak.
  4. Tick: socials live.

11:00 — Email Wave 1 waitlist

  1. Send the Wave-1 stealth-waitlist activation email (BCC, batched in groups of 50, 5-minute spacing).
  2. Subject line variant tested with three preview tools.
  3. Tick: waitlist activated.

12:00 — Office hours begin

  1. Open a Discord/Slack channel for new signups.
  2. Open the Sentry dashboard, the CFWA dashboard, the Stripe dashboard, the Anthropic console — all in tabs.
  3. Live-monitor for the next 6 hours minimum.
  4. Reply to every Show HN comment within 30 minutes for the first 6 hours.
  5. Don’t reply defensively. Don’t argue. Thank, clarify, fix.

T+1 day — first response cycle

  • [ ] Re-read every Show HN comment + reply to anything still unanswered
  • [ ] Tweet a follow-up: “Thank you. Here’s what surprised me.” (concrete + specific)
  • [ ] Repost the top reactions on Bluesky
  • [ ] Review Sentry: triage every error, no matter how small (issue + fix + ship)
  • [ ] Review Anthropic spend tracking — flag any anomaly that suggests abuse
  • [ ] Review Stripe — first paying customer? (Tweet about it with their permission)
  • [ ] Send “thanks for joining” follow-up to everyone who signed up via Show HN
  • [ ] Open a docs/launch/RETRO_DAY_1.md file and start jotting raw observations

T+7 days — Product Hunt + first retro

  • [ ] Product Hunt launches at 12:01 AM PT (auto-scheduled)
  • [ ] Hourly check-ins for the first 6 hours (PH community is timezone-clustered)
  • [ ] Reply to every PH comment within 1 hour
  • [ ] First weekly retrospective: top 3 learnings, top 3 follow-ups, top 3 surprises
  • [ ] Review weekly metrics:
  • Signups (raw + activated, where “activated” = at least one save + one publish)
  • NPS (from any Wave-2 user who’s responded to the in-app survey)
  • Churn (deactivations, account deletions)
  • Anthropic spend $ / signup
  • [ ] First blog follow-up published: case study of a Wave-2 user (with permission), in the founder’s-letter voice
  • [ ] Open a docs/launch/RETRO_WEEK_1.md file consolidating the week’s notes

Rollback procedures

If anything goes catastrophically wrong, these are the panic-button procedures. Practiced once during T-3.

DNS swap-back (target: <5 minutes)

  1. Update apex A record back to the staging IP.
  2. dig +short ensemble.tld @1.1.1.1 confirms the rollback within 90s (TTL=300).
  3. UptimeRobot should flip green within one cycle (5 min).
  4. Public sees the staging “We’re back shortly” page.

Cloudflare Access emergency-disable

  • wrangler config edit + wrangler deploy — Access policy can be toggled off in <60s if a real user is locked out.
  • Emergency contact: Cloudflare support is paid-tier; ticket-based.

Anthropic spend emergency cap

  • state.json.anthropic.daily_cap_usd — set to a lower number (e.g., $5).
  • The orchestrator’s autopilot freeze respects this within one cycle.
  • If the cap is already exceeded and the cause is abuse, set state.json.autopilot_freeze_until = "9999-12-31T23:59:59Z" to fully freeze.

Public freeze (“kill switch”)

  • Worst case: a serious vulnerability shipped. Rollback DNS + freeze autopilot + post a status-page note.
  • The status page lives at status.ensemble.tld (see docs/operations/UPTIME_MONITOR_SETUP.md).
  • Rule: never delete data on a freeze. We can always re-enable. We can’t undelete.

Sign-off

The launch is “go” only if every box above is ticked AND Kevin has slept at least 7 hours the night before. Don’t ship tired.

If something is unticked at T-1 day 23:00, the launch slips. That’s the contract.
