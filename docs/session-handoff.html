Known issues + pitfalls (so you don’t step on them)

  1. git push from a feature branch sometimes goes to the feature branch instead of main. Earlier today I committed to a feature branch by accident, had to cherry-pick to main, and accidentally REGRESSED main twice with feature-branch versions of dashboard-generate.sh that were missing recent work. The fix that’s been ironclad since: git checkout main BEFORE the commit, verify with git branch --show-current, then commit. Never git checkout <hash> -- file to copy a file from another branch unless you’ve manually verified the file is up to date with main.

  2. Markdown library on Python 3.14 (homebrew default). It’s not in the default site-packages; render_doc silently returns None and leaves stale doc pages. Fix: pip3 install --break-system-packages markdown. Already installed in this Mac’s environment but worth knowing if Python upgrades break it again.

  3. The top-level .gitignore has chats/ (line 11). This excludes the runtime ~/.claude/orchestrator/chats/*.json directory from version control (correct), but it ALSO excludes any sub-directory named chats/ (e.g. bin/dashgen/chats/ — which is why we renamed to bin/dashgen/data/). Avoid creating new directories named chats anywhere.

  4. Per-project pages use the legacy head_block + linked style.css pipeline. Hub pages use SHARED_HEAD (inline). They look similar but live on different rails. Earlier “true unification” attempts caused CSS specificity collisions that broke per-project layout. Phase 2 of the A-tier plan is the careful path to actually unify them.

  5. Scheduled-task auto-approver dislikes dynamic bash. SKILL.md files with $$ / $(...) get denied → zombie sessions hold the per-task limit. Fix: wrap in static-path scripts (bin/dashboard-fire.sh, bin/weekly-report.sh) and add explicit permission rules in ~/.claude/settings.local.json. Already done for current scheduled tasks.

  6. Safari “Add to Dock” creates a Web App at ~/Applications/Ensemble.app. Don’t confuse with the native Ensemble.app at plugins/ensemble/integrations/macapp/Ensemble.app (or installed at /Applications/Ensemble.app). The Safari one has CFBundleIdentifier: com.apple.Safari.WebApp.<UUID> and contains no executable code.
