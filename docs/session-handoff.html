8. Three-layer autopilot mutex with user-controlled cap

Existing orchestrator_lock.sh hook gates MCP tool calls at the kernel level — bulletproof for computer-control (workshop) collisions. This directive layers TWO additional protections at spawn time, then exposes a user-controlled concurrency cap on top.

Locked safety layers (always on, never disabled):

  1. Workshop lock (existing) — global lock on MCP tool calls (computer-use, Preview, Chrome). Two chats can NEVER both grab the computer/browser. Kernel-enforced, no bypass.
  2. Per-project spawn lock (new) — per-slug lock dir state.spawn-lock-<slug>.d/. Two autopilot subprocesses can NEVER target the same project simultaneously. Prevents same-repo file-stomp.
  3. Resource floor (new, opt-in, default OFF) — pre-spawn check: if system RAM/CPU is critically taxed, refuse with “system busy, retry in N min”. Power-user knob.

User-controlled concurrency layer:

  • max_concurrent_autopilots field in state.json. Default: 2. Range: 1 to whatever the machine handles (no hard ceiling).
  • Adjustable via verbal command (set max autopilots to 3) OR PWA dashboard pill (live counter “Autopilots: 1/2 running” — tap to adjust).
  • Soft guardrail: if user sets ≥ 4, one-time confirm: “You’re scaling beyond the tested range. Monitor system load. Confirm?”
  • When cap hit: queue with 5-minute timeout (Kevin’s locked decision). New fire waits in state.spawn-queue.json up to 300s for a slot to open, then refuses with clear message.

Spawn flow:

User/cron fires autopilot for project <slug>
  ↓
Is <slug> already running? (per-project lock check) → Yes → REFUSE
  ↓ No
Is len(active_autopilots) >= max_concurrent? → Yes → QUEUE (5min timeout)
  ↓ No
Is resource floor enabled AND system taxed? → Yes → REFUSE
  ↓ No
Acquire state.spawn-lock-<slug>.d, register {pid, slug, started_at} in
  state.active_autopilots[<slug>], exec claude -p, trap EXIT releases lock

If any spawned autopilot reaches for computer-control, the existing workshop lock catches contention with other chats. Stack is: workshop (global) + spawn (per-project) + cap (user knob).
