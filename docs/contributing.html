Contributing

How to contribute to the Ensemble.

source: CONTRIBUTING.md

The Ensemble is a personal project, currently in private preview. Public contribution is not yet open — but if you find a bug, have a security concern, or want to suggest something, this is how to do it.

TL;DR

  • Bugs: open a GitHub issue using the bug template
  • Security: see SECURITY.md (do not open public issues for vulnerabilities)
  • Features / ideas: open a discussion or use the feature-request template
  • Code: if you really want to send a PR, read this file first

The contract

Every change to this repo follows the Edit & Code Discipline — non-negotiable rules baked into every chat that operates here:

  1. Touch only what the task requires. No drive-by refactors. No opportunistic formatting.
  2. Retain all other elements unless explicitly removing them.
  3. Never leave dead code. No commented-out blocks. No orphan imports. No TODO: fix later.
  4. When removing, remove cleanly. Delete the code, update callers, verify nothing references it.

If your change doesn’t follow this, we’re going to disagree about how it lands.

Commit messages

  • First line ≤ 72 chars in imperative mood: "Fix lock release race when..." not "Fixed lock release race when..."
  • Body explains why, not just what (the diff shows what)
  • Co-authored-by trailer for AI-pair-programmed commits — every commit by the Ensemble’s autopilot/Maestro/Agents includes: Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
  • No [autopilot] prefix on human-authored commits — that prefix is reserved for autopilot sessions so we can git log --grep '\[autopilot\]' to audit machine-only work.

Testing

This is a shell-script + plugin-prompt project, so testing means:

  • Lock-race smoke — bash plugins/ensemble/bin/test_lock_race.sh from a clean repo. Should report 10/10 rounds passed.
  • Routine prelude smoke — ROUTINE_NAME="smoke" bash plugins/ensemble/bin/routine_prelude.sh. Should print PRELUDE_OK: ….
  • Hook unit pre-flight — the .github/workflows/integration-test.yml covers JSON validity, plugin manifest schema, lock-race concurrency, and PreToolUse hook unit tests. CI is currently disabled pending billing resolution; run locally: bash bash -c 'set -e; for f in plugins/ensemble/bin/*.sh; do bash -n "$f"; done; echo OK'
  • Live diagnostic battery — there’s a 1-minute battery captured in earlier session logs; periodic re-runs land in docs/HEALTH.md (when generated).

Branching

  • main — protected. CI gates on the workflow file (currently disabled).
  • Feature branches — name like gap-N-<description> for mission-roadmap work, feat/<area> for new capabilities, fix/<area> for bugs.
  • PR target — always main. Squash-merge preferred to keep history readable.

Cross-repo work

The Ensemble’s source-of-truth is this repo (claude-ensemble). Three companion repos sync from canonical:

  • KiwiMaddog2020/ensemble-config — cross-machine sync layer (templates + memory + bin-mac/bin-win)
  • KiwiMaddog2020/website-agent-starter — friend-shareable starter for the website-agent
  • KiwiMaddog2020/ensemble-dashboard — public dashboard generated by bin/dashboard-generate.sh

If your change affects a synced file, the sync to companion repos is the responsibility of the same PR (or a follow-up commit on main).

What to avoid

  • Don’t bypass the lock. Don’t write state.json.active_autopilot_chat or state.lock.d/ unless you’ve followed the acquire protocol.
  • Don’t skip the prelude. Every scheduled task starts with routine_prelude.sh. Mode gates + work-hours respect live there.
  • Don’t add narration comments. Per AGENT.md §3 — only write a comment when the WHY is genuinely non-obvious and no identifier name can carry it.
  • Don’t introduce a build step. This stays vanilla shell + Python stdlib + no JS frameworks. Tempted? STOP and ask.
