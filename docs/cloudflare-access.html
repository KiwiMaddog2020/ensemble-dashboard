Cloudflare Access

Auth-gate the public PWA + HTML sites. ~30 min setup.

source: plugins/ensemble/integrations/cloudflare-access/README.md

The Ensemble’s public-facing assets — ensemble-dashboard (PWA), public/index.html + public/dossier.html (marketing), ensemble-phone, ensemble-desktop — should require login before rendering. Cloudflare Access is the cleanest free path: real auth, no hosting migration, ~30 min one-time setup.

What you get

  • Login page in front of every URL — magic-link email OR Google / GitHub OAuth
  • Free for up to 50 users (way more than the Ensemble needs)
  • PWA installs respect the auth: first launch on each device requires login
  • Audit log of every successful + failed login
  • Optional: device posture checks (only authorize known devices)
  • Doesn’t move hosting — your GitHub Pages backend stays put; Cloudflare just sits in front

Prerequisites

  • A domain you control (example.com) OR willingness to use a *.workers.dev Cloudflare-provided subdomain
  • A Cloudflare account (free tier; sign up at cloudflare.com)
  • Access to your domain’s DNS records (if using your own domain)

Setup walkthrough

Step 1 — Sign up for Cloudflare (one-time, ~2 min)

  1. Go to cloudflare.com, sign up free
  2. Verify email
  3. From the dashboard, navigate to Zero Trust in the left sidebar (creates a free Zero Trust org on first click)

Step 2 — Add your domain (one-time, ~5 min)

If you already have a domain:

  1. Cloudflare dashboard → Add a Site
  2. Enter your domain (e.g. your-ensemble.com)
  3. Choose Free plan
  4. Cloudflare will scan existing DNS; review and click Continue
  5. Update nameservers at your registrar to the two Cloudflare-provided nameservers (Cloudflare emails the values)
  6. Wait ~5 min for DNS to propagate; status flips to “Active”

If you don’t have a domain:

  1. Buy one through Cloudflare (~$10/year for .com) — they auto-configure
  2. OR use a workers.dev subdomain (no domain purchase needed but uglier URL)

Step 3 — Add a CNAME pointing at GitHub Pages

In Cloudflare → DNS → Records:

Type:    CNAME
Name:    ensemble (or whatever subdomain you want — gives you ensemble.your-domain.com)
Target:  kiwimaddog2020.github.io
Proxy:   ON (orange cloud — REQUIRED for Access to work)

Step 4 — Configure GitHub Pages custom domain

In your ensemble-dashboard repo → Settings → Pages:

  • Custom domain: ensemble.your-domain.com
  • Enforce HTTPS: ON (after the cert provisions, ~15 min)

This makes GitHub Pages serve the dashboard at the new URL.

Step 5 — Create an Access application (the auth gate)

In Cloudflare → Zero Trust → Access → Applications → Add an application:

  1. Type: Self-hosted
  2. Name: Ensemble Dashboard
  3. Subdomain: ensemble (or whatever you used)
  4. Domain: your-domain.com
  5. Path: leave blank (gates everything)
  6. Session duration: 24 hours (or your preference; longer = less friction, shorter = more security)

Step 6 — Add a policy

Define who can log in:

  • Policy name: My access
  • Action: Allow
  • Configure rules → Include → Emails → list of allowed emails (just yours for now; add friend/team emails later)

OR use GitHub OAuth if you only want yourself / your GitHub org members:

  • Cloudflare → Zero Trust → Settings → Authentication → Add a login method → GitHub
  • Then in your Access policy, Include → GitHub → your username/org

Step 7 — Enable identity provider (IdP)

In Zero Trust → Settings → Authentication, the default “One-time PIN” (magic-link email) is enabled by default. Optionally add Google / GitHub / etc.

Step 8 — Test

  1. Open an incognito window
  2. Visit https://ensemble.your-domain.com
  3. Cloudflare’s login page appears asking for email
  4. Email arrives with the magic link
  5. Click the link → redirected back to your dashboard, logged in
  6. Re-test: dashboard loads directly because session cookie is valid

Step 9 — PWA install

After logging in once on a device, install the PWA via “Add to Home Screen”:

  • iOS: Safari → Share → Add to Home Screen
  • macOS: Safari → File → Add to Dock
  • Android: Chrome → menu → Add to Home screen

Cookie persists in the PWA shell. Re-login on session expiry.

Step 10 — Update Ensemble references

Once auth is live and tested, update places that reference the public URL:

  • bin/dashboard-generate.sh — DASHBOARD_URL env var defaults
  • plugins/ensemble/integrations/swiftbar/ensemble-autopilot.10s.sh — dashboard link
  • public/index.html (marketing) — same domain, same auth (separate Access app or include path)
  • README badges, MOBILE_DISPATCH.md walkthroughs

Multiple sub-paths under one Access policy

If you want phone + desktop cheat sheets behind the same auth:

  • Add CNAMEs for each (phone.your-domain.com, desktop.your-domain.com)
  • Create an Access application for each, OR one app with multiple subdomain entries
  • Same policy can cover all of them

Costs

  • Free tier: 50 seats (way more than enough)
  • Paid: $7/user/month if you ever exceed 50 (you won’t)

Rollback

If anything breaks, you can disable Access without losing the GitHub Pages backend:

  • Cloudflare → Zero Trust → Access → Applications → toggle the app to Disabled
  • DNS still routes through Cloudflare; site is now public again
  • OR set proxy off (grey cloud) → Cloudflare bypassed entirely, GitHub Pages serves directly

Alternatives considered

  • Client-side password gate — basic JS check, breakable via DevTools. Good MVP only.
  • Tailscale-only — fully private but loses any public access for demos.
  • Vercel/Netlify migration — real auth via their platforms but moves hosting off GitHub Pages.

Cloudflare Access wins on: real security + free + keeps GitHub Pages + supports PWA + audit log.

When to do this

Before public-flipping claude-ensemble and submitting to the Claude marketplace. The marketplace listing will surface the dashboard URL to users; auth-gating is mandatory before that point.

For private preview (current state): nice-to-have. Most random visitors won’t find the URL.
