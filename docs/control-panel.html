Control Panel

Mac-local Python server, Bearer auth, embedded chat.

source: docs/CONTROL_PANEL_PLAN.md

Drafted 2026-04-25 after Kevin’s directive: “expand upon the dashboard idea and make a pwa of sorts that actually integrates with claude. buttons that can turn autopilot mode or auto-tests on or off and things of that nature, an adaptive ui that lets us orchestrate the whole thing” + “i want users to be able to sign into their own, and it should auto set up their own dashboard in a github page free hosted format to make things easy. ultimate control with a gui over the whole Ensemble.”

Vision

The Ensemble plugin gives every user their own private control panel — a hosted dashboard (free GitHub Pages) that shows their projects’ state, lets them toggle autopilot/modes/active flags with a click, fire autopilot sessions, and chat with Claude directly inside the same UI. No CLI required for day-to-day operation; the GUI is the primary surface.

Two clean shapes — public read + private write

The dashboard splits into two responsibilities, hosted differently:

Public read layer — <their-username>.github.io/ensemble-dashboard/

  • Static HTML auto-generated 3x daily by the Dashboard Update routine
  • Shows: project roster, completion %, evolution mode pills, last-seen timestamps, per-project pages with timelines
  • Anyone with the URL can view (it’s GitHub Pages public)
  • Already shipped today as v1; this layer continues working as-is

Private write layer — local Mac HTTP server

  • Python stdlib http.server subclass listening on 127.0.0.1:8080 + Tailscale IP
  • Serves the same HTML as the public layer (so the URL works whether you’re on the public site or hitting your Mac directly), plus extra interactive button affordances
  • POST endpoints:
  • POST /toggle-active — flip active for a slug
  • POST /set-mode — change evolution_mode
  • POST /toggle-autopilot — flip autopilot_eligible
  • POST /fire — trigger mobile_dispatch.sh fire <minutes> <prompt> <slug>
  • POST /kill — fire the kill switch
  • GET /state — current runtime state JSON
  • Auth: Bearer token from ~/.claude/orchestrator/.env.local (DASHBOARD_TOKEN=...) sent in every write request. Tailscale provides network-layer security; Bearer adds a second factor.

Adaptive UI — single page detects which layer it’s on

The dashboard JS does a startup probe: 1. Try GET http://<tailscale-ip>:8080/state (or localhost:8080/state if running locally) 2. If reachable + auth OK: show interactive buttons next to every flag/pill, plus the “Fire autopilot” + “Kill switch” controls 3. If not reachable: stay read-only (graceful fallback)

Same HTML works for both modes; JS hides/shows the controls based on probe result.

Embedded Claude chat — iframe to claude.ai/code

Approved option 1 from earlier AskUserQuestion. The dashboard reserves a panel (right side on desktop, bottom sheet on mobile) for an <iframe src="https://claude.ai/code">. The user is already signed in via browser cookie; the iframe inherits the session.

Fallback for X-Frame-Options blocks: If claude.ai sets DENY or SAMEORIGIN, we detect the failed load and replace the iframe with a “Launch Claude →” button that opens claude.ai/code in a new tab. UX is slightly worse but not broken.

Auto-setup for any user

Per Kevin’s productization vision, when ANY user installs the Ensemble plugin (via Claude Code marketplace), the plugin auto-deploys their own private dashboard. Flow:

  1. Trigger: First-run hook fires the moment plugin is installed (e.g., plugins/ensemble/.claude-plugin/plugin.json declares an install hook).
  2. Detect prerequisites: verify gh CLI installed + authenticated. If not, surface install instructions.
  3. Create their repo: bash gh repo create <their-username>/ensemble-dashboard --public --description "My Ensemble project roster"
  4. Push initial dashboard: Run bin/dashboard-generate.sh against an empty chats/ dir → push the result.
  5. Enable GitHub Pages: bash gh api -X POST repos/<their-username>/ensemble-dashboard/pages \ -f 'source[branch]=main' -f 'source[path]=/'
  6. Wire scheduled task: Install the Dashboard Update routine into their ~/.claude/scheduled-tasks/.
  7. Generate local server config: Write ~/.claude/orchestrator/.env.local with a freshly-generated DASHBOARD_TOKEN.
  8. Print the URL: Your dashboard: https://<their-username>.github.io/ensemble-dashboard/

The user does nothing manual. The plugin handles setup; the dashboard auto-updates from then on.

Tonight’s v1 (executable scope)

For Kevin’s own Ensemble (productization extends to all users in a follow-up session):

  • bin/control-panel-server.sh — wrapper that launches the Python HTTP server on 0.0.0.0:8080 (Tailscale-reachable). Registers a launchd agent so it stays running across logouts.
  • bin/control-panel-server.py — the actual server. Stdlib http.server, ~150 lines. Endpoints listed above.
  • bin/dashboard-generate.sh extension — adds interactive controls to the rendered HTML (data-attributes that the JS can find + wire up).
  • JS in dashboard pages — startup probe + button wiring (~100 lines, embedded in HTML at gen time).
  • launchd/com.kevin.ensemble.control-panel.plist — keep-alive plist for the server.

Estimated effort: ~2 hours for v1 working end-to-end on Kevin’s machine.

Out of scope for now

  • Multi-user-per-instance (each user has their own instance; not multi-tenant in one)
  • Cloud-hosted server (Vercel/Cloudflare/etc.) — Mac-local is simpler + private
  • Public write API — write actions are always Tailscale-only
  • Real-time push (websockets) — auto-refresh + 30s JS polling is sufficient
  • Mobile push notifications from button actions — Pushover already wired; can add later

Acceptance criteria for v1 (tonight)

  • [ ] Local server starts via launchd on Mac boot
  • [ ] curl http://localhost:8080/state returns current runtime JSON
  • [ ] curl -X POST http://localhost:8080/toggle-active -H "Auth: Bearer $TOKEN" -d '{"slug":"boo-website"}' flips the active flag
  • [ ] Dashboard at localhost:8080/ shows interactive buttons (toggles, mode picker, fire button)
  • [ ] Same dashboard at https://kiwimaddog2020.github.io/ensemble-dashboard/ shows read-only (no buttons because the probe fails over the public network)
  • [ ] iframe to claude.ai loads (or graceful fallback if blocked)
  • [ ] Tailscale-reachable from phone: http://100.107.120.85:8080/ works on phone Safari with Bearer token in localStorage
