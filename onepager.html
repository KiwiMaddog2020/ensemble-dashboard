The problem

Two automations, one test bench.

Run multi-chat Claude Code workflows on real projects and the moment automation enters the picture, things break. Two chats fire test runners at the same simulator. Both grab port 8000. Both write to the same fixture files. Both kick off xcodebuild in the same DerivedData. The simulator state becomes a Frankenstein of two independent runs — false greens in one chat, mysterious reds in the other, and the code that "passed" is broken on disk. Without a control plane, parallel automation corrupts the very signal you're trying to read.

Without orchestration

Tests collide. Builds trample. Signals lie.

Chat A spins up the simulator to run the unit suite. Chat B fires its own test fixture into the same simulator 10 seconds later — wiping A's state mid-run. A reports failures that aren't real. B reports passes that aren't either. Meanwhile both push commits with conflicting "fixes." An hour reconstructing what happened from git reflog and a dirty DerivedData.

With Ensemble

Code in parallel. Test in single file.

Many chats code in parallel — each in its own repo, no contention, no lock needed. The Maestro hands the autopilot baton to one chat for testing only; tests are what share machine resources (simulator, ports, fixtures, DerivedData), so tests are what gate. Other chats keep writing code, planning, reviewing, drafting docs while one chat tests. When the test session releases the lock, the next chat picks it up. Filesystem-enforced. Race-impossible. Every test result is real because test runs never collide on the same machine — no matter how many chats are running.

The real win

Plan, code, test, calibrate. Repeating.

This is where it shines. Schedule chats to rotate through the loop. While one chat tests in the simulator, another plans the next feature, a third commits and pushes a fix. Claude takes over automation controls and testing himself, then goes back in to fix what failed. You check in when ready.

Plan

An Agent reads its charter, surveys the current state, surfaces the next unit of work as a click-button decision. You approve in one tap.

Code

The Agent writes code freely — no lock needed. Each chat works in its own repo, on its own files. Many chats can code in parallel without colliding because nothing yet touches shared machine state.

Test

The lock activates here. Tests share the simulator, ports, fixtures, and DerivedData — only one chat runs them at a time. The Agent acquires the autopilot baton, runs the suite, captures results. Other chats keep coding while testing happens.

Calibrate

If tests fail, the Agent diagnoses, fixes, retries — within budget. On success, surfaces the next decision. Loop continues, or pauses for your review.

Trust by design

Every safeguard is mechanical.

Not policy. Not honor system. Filesystem locks, atomic operations, distributed kill-switches. Engineered like a power plant — multiple independent safeguards, all visible, all auditable.

Three-layer mutex

Workshop lock (computer/browser contention) + per-project spawn lock (file-stomp prevention) + opt-in resource floor (RAM/CPU pre-check), with a user-controlled max_concurrent_autopilots cap. Cap-hit = queue with 5-min timeout. POSIX-guaranteed atomic mkdir; you can't fake holding any lock.

Distributed kill-switch

Type ***ORCHESTRATOR OFF*** in any chat — verbatim, on its own line — and the six-phase shutdown cascade fires. Releases locks, pauses automations, flips to direct mode. Idempotent, race-safe.

Safety constraints

Destructive git ops, App Store / Play Store / TestFlight submissions, deploys beyond GitHub Pages, billing changes, public-flips of private repos — all gated. Agents must escalate; you approve in chat.

Hard duration ceilings

Every autopilot session runs under gtimeout (N+2)m. If it overruns, the wrapper kills it. Process tree swept on kill — parent, timeout wrapper, claude-p grandchild, all SIGKILL'd.

Mode gates

Routines no-op silently when state.json.mode ≠ orchestrated or mode_transitioning == true. No surprise fires during your kill-switch cascade.

Full audit trail

Every run writes to runs/autopilot-<stamp>.md + raw .raw.log. Every commit is attributed. Every state transition logged. Nothing happens silently.

What's inside

Everything you need to ship the loop.

Six-state lifecycle

Building → Launch Prep → Warmer ⇄ R&D ⇄ Updates → Hibernating. Auto-transitions at G1/G7/G8. Live triangle is bidirectional. Each state colored on the dashboard.

Smart handoff

Self-monitor context. 80% warn → 90% stage → 95% hard-stop with paste-ready resume prompt. No chat dies in the middle of a thought.

Turbo mode

Say "turbo" in any chat. All approvals up-front, then run autonomously until completion. Safety gates still fire; thinking still Apple-grade.

Phone-triggered autopilot

Termius + Tailscale SSH. Tap a snippet, fire a session. One-line ack back to your phone.

Rapid-fire UX (with toggle)

Every decision is a click-button. Voice-friendly numbering. Slot 4 always reserves "Disable Rapid Fire Mode" — one-click escape hatch.

Outside-the-box thinking

Priority 1 operating posture. Build calibration tools when warranted (isolate each CSS effect on its own row to spot a glitch). Thoughtful, not gimmicky.

Feedback pipeline

Sunday 6am aggregator pulls from each live project's channel. Strict plan-then-approve gate for live products — no surprise UX shifts.

Tier 1 hardening

caffeinate -i wraps every fire (no Mac sleep mid-run). Battery + disk pre-flight. Log rotation Sunday 5am. 30/60/90-day retention.

Menu bar indicator

SwiftBar plugin shows ☕ + active count when autopilot is running. Click → project list, queue, Stop All. One-shot installer. Hidden when idle.

PWA dashboard

Live cross-project roster. State pills with color-coded lifecycle stage. Tap-to-fire-autopilot. Installable to phone home screen.

Cross-platform parity

macOS + Linux native (bin/) + Windows native (bin-win/ PowerShell). Three-layer mutex ports to both. Hand-maintained parity.

Lint discipline

EditorConfig + markdownlint + yamllint + ruff + prettier — configs at every repo root, CI gates on every PR. Surgical edits never introduce new lint failures.
